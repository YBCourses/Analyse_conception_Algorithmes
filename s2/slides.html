Chapitre 1

La mémoire en C

Où vivent les données d’un programme, et comment désigner un endroit de la mémoire ?

Une variable est une case mémoire

Une variable est une case de la mémoire qui a trois choses : un nom, une valeur et une adresse.
L’adresse est le numéro de la case, comme le numéro d’un casier. Elle ne change jamais pendant la vie de la variable.
Un int occupe 4 octets : voilà pourquoi les numéros de cases voisines sont espacés de 4 (100, 104, 108…).

Les variables locales

Une variable locale est une variable déclarée à l’intérieur d’une fonction. Elle n’existe que pendant l’exécution de cette fonction.
  1. Elle naît quand le programme exécute sa déclaration.
  2. Elle meurt quand la fonction se termine : sa case est rendue et son contenu est perdu.
  3. Elle est rangée dans la zone appelée la pile, gérée automatiquement.
void compter(void) {
    int x = 10;    // x naît ici
}                  // x meurt ici

int main(void) {
    int a = 5;     // a naît ici
    compter();
    return 0;
}                  // a meurt ici
Dans les simulations qui suivent, la colonne PILE montre les variables locales vivantes. Chaque case porte son numéro, son nom et sa valeur.

Le pointeur : une variable qui contient une adresse

Un pointeur est une variable dont la valeur est l’adresse d’une autre case. On dit qu’il désigne cette case. On dessine souvent cela par une flèche.
Image : un papier sur lequel on a écrit « casier n° 100 ». Le papier n’est pas le casier, mais il permet de le retrouver. Le nombre écrit sur le papier est la valeur du pointeur.
int *p
déclare un pointeur p vers un entier
&a
se lit « l’adresse de a » : un numéro de case
*p
se lit « la case dont l’adresse est dans p »

Objectif

À observer

À essayer

NULL : le pointeur qui ne désigne rien

NULL est une valeur de pointeur qui signifie « ne désigne aucune case ». On le dessine sans flèche.
Suivre un pointeur NULL (écrire *p) fait planter le programme.
Bon réflexe : if (p != NULL) { … } avant de suivre un pointeur. NULL sert aussi à marquer la fin d’une liste.

malloc, free et sizeof

sizeof(int)
Le nombre d’octets occupés par un type. Pour un int : 4.
malloc(n)

free(p)

Un pointeur vers un pointeur

Un pointeur est une variable comme les autres : elle a elle-même un numéro de case. On peut donc ranger son adresse dans un autre pointeur.
Image : un papier dit « le prochain papier est dans le casier 104 », et le casier 104 contient un papier qui dit « le trésor est dans le casier 100 ».
int **pp : pointeur vers un pointeur vers un entier. Une étoile de plus = un niveau de flèche de plus.

Application : la tête d’une liste

C’est exactement le même problème : la tête d’une liste est un pointeur, Noeud *tete, et une fonction d’insertion doit pouvoir le modifier.

Ne marche pas
void inserer(Noeud *tete, int v)
La fonction reçoit une copie de tete. Elle peut changer la copie, mais la variable de l’appelant reste inchangée : l’insertion est perdue (et le nœud, fuite).
Marche
void inserer(Noeud **tete, int v)
La fonction reçoit l’adresse de tete. *tete est la variable de l’appelant. On l’appelle avec inserer(&tete, 5).
Noeud ** : pointeur vers un pointeur vers un nœud. Même schéma que int ** : la liste sera modifiable depuis une fonction.

Chapitre 2

Tableau ou liste ?

Pourquoi inventer une autre structure, puisqu’on sait déjà utiliser des tableaux ?

Le tableau : ses forces et ses limites

Force

Accès direct

t[i] coûte une opération : l’adresse se calcule, début + i × 4.
Pour t[3] : 200 + 3 × 4 = 212. Un calcul, pas de parcours.
Limites

Taille fixe, insertions coûteuses

  • La taille est fixée à la création : pour agrandir, il faut tout recopier.
  • Pour insérer au début ou au milieu, il faut décaler des cases pour faire de la place.
  • Les cases doivent être voisines : un grand tableau exige un grand bloc libre d’un seul tenant.
Combien d’opérations pour insérer au début ? Réponse à la diapositive suivante.

Insérer au début d’un tableau

Objectif
Compter les opérations nécessaires pour insérer une valeur au début d’un tableau.
À observer
Chaque élément est décalé d’une case vers la droite, en commençant par le dernier. Le compteur compte les décalages.
À essayer
Essayez n = 4, 5 puis 8 : quel est le lien entre n et le nombre de décalages ?

Le coût : n décalages

nDécalagesSi 1 décalage = 1 ns
1 0001 0001 µs
1 000 0001 000 0001 ms
1 000 000 0001 000 000 0001 s
Insérer au début d’un tableau de n éléments coûte n décalages : Θ(n), famille linéaire.
Si on insère souvent au début, ce coût se répète à chaque insertion : pour n insertions, environ n²/2 décalages.
Peut-on insérer au début sans rien décaler ? C’est possible si les éléments n’ont pas besoin d’être voisins en mémoire.

Une autre idée : la chasse au trésor

Dans une chasse au trésor, chaque indice ne donne que l’emplacement du suivant. Les indices peuvent être cachés n’importe où.

Indice 1
« Le prochain indice est dans le casier 12. »
Indice 2 (casier 12)
« Le prochain indice est dans le casier 47. »
Indice 3 (casier 47)
« Il n’y a plus d’indice : fin du jeu. »
Pour ajouter un indice au début, il suffit d’en écrire un nouveau qui désigne l’ancien premier. On ne déplace rien.
Au lieu de cases voisines, on met dans chaque élément l’adresse du suivant. C’est la liste chaînée.

Chapitre 3

La liste chaînée

Comment relier des données dispersées dans la mémoire ?

Le nœud : une valeur et l’adresse du suivant

Un nœud est un petit bloc du tas qui contient une valeur et l’adresse du nœud suivant.
On le dessine par deux cases : la valeur et le pointeur « suivant ».

Une liste : une tête, des nœuds, NULL à la fin

La têteLa variable tete est la seule entrée de la liste : elle désigne le premier nœud.
Les nœudsIls sont dispersés dans le tas. Leurs adresses ne se suivent pas, seules les flèches les relient.
La finLe dernier nœud pointe vers NULL. C’est ainsi que l’on sait que la liste s’arrête.

À essayer
Avant chaque avancée, prédisez la valeur qui va être affichée.

À observer

À essayer

Insérer à la fin de la liste

Objectif
Insérer un nœud à la fin, alors qu’on ne connaît que la tête.
À observer
Le nombre d’avancées de courant avant de tomber sur le dernier nœud.
À essayer
Comptez les avancées. Combien y en aurait-il avec 1 000 nœuds ?

Insérer à la fin : un coût de n

Il faut parcourir toute la liste pour trouver le dernier nœud : n − 1 avancées.
Insérer à la fin : Θ(n).
Astuce : on peut mémoriser en plus une variable queue qui désigne le dernier nœud. L’insertion en fin devient alors Θ(1).
Il faut alors mettre à jour queue à chaque insertion en fin et à chaque suppression du dernier nœud.

Rechercher une valeur : pas de raccourci

courant ← tete
tant que courant ≠ NULL faire
    si courant.valeur = x alors
        retourner courant
    courant ← courant.suivant
retourner NULL
C’est la recherche séquentielle de la séance 1 : Θ(n) au pire.
Impossible d’utiliser la recherche dichotomique : elle exige d’aller directement au milieu, et une liste n’offre pas d’accès direct.

Supprimer un nœud

Objectif
Supprimer un nœud sans casser la liste ni oublier de libérer sa mémoire.
À observer
Le nœud est d’abord court-circuité par une flèche, puis libéré (hachuré).
À essayer
Jouez « au milieu » puis « le premier » : pourquoi faut-il une variable temp dans le second cas ?

Libérer toute la liste

courant ← tete
tant que courant ≠ NULL faire
    suivant ← courant.suivant
    libérer(courant)
    courant ← suivant
tete ← NULL
Il faut garder le suivant avant de libérer. Après libérer(courant), lire courant.suivant serait lire un bloc déjà rendu.
À la fin, tete ← NULL : la liste est vide, et plus aucun bloc n’est perdu.
Un passage sur chaque nœud : Θ(n).

Deux variantes à connaître

Liste doublement chaînée
Chaque nœud connaît son précédent et son suivant : on peut parcourir dans les deux sens, et supprimer un nœud sans parcours préalable.
Prix : un pointeur de plus par nœud.
Liste circulaire
Le dernier nœud désigne de nouveau le premier. Utile pour tourner en boucle : tourniquet de tâches, jeu à tour de rôle.
Attention : plus de NULL, il faut un autre critère d’arrêt.

Pile d’assiettes

On pose et on prend l’assiette du dessus. Celle du dessous attend.
Une pile est une structure où l’on n’ajoute et ne retire que par le dessus : le dernier entré est le premier sorti. En anglais : LIFO (last in, first out).

Les opérations d’une pile

OpérationEffetCoût

Pile vide : dépiler ou lire le sommet est une erreur. On teste est_vide() avant.
Pile pleine : possible seulement si la pile est faite avec un tableau de taille fixe.

Manipulez une pile

Objectif

À observer

À essayer

Deux façons de construire une pile

Avec un tableau 
empiler(x):
    sommet ← sommet + 1
    t[sommet] ← x
dépiler():
    x ← t[sommet]
    sommet ← sommet - 1
    retourner x
Simple et rapide, mais la taille est limitée : risque de pile pleine.
Avec une liste chaînée 
empiler(x):
    insérer x en tête
dépiler():
    x ← tete.valeur
    supprimer la tête
    retourner x
Pas de limite de taille. On réutilise l’insertion et la suppression en tête du chapitre 3 : toutes deux en Θ(1).
Dans les deux cas, toutes les opérations coûtent Θ(1).

La dernière parenthèse ouverte doit être la première fermée : c’est exactement le comportement d’une pile.
  1. Ouvrante : on l’empile.
  2. Fermante : on dépile et on vérifie que cela correspond.
  3. À la fin, la pile doit être vide.

Application 2 : la notation postfixe

Dans la notation postfixe, l’opérateur est écrit après ses deux opérandes. Pas de parenthèses, pas de priorités.
HabituelPostfixe
3 + 43 4 +
(3 + 4) × 23 4 + 2 *
3 + 4 × 23 4 2 * +
Algorithme d’évaluation
  1. Un nombre : on l’empile.
  2. Un opérateur : on dépile deux nombres, on calcule, on empile le résultat.
  3. À la fin : un seul nombre reste, c’est le résultat.
Les calculatrices à pile et certains langages utilisent cette notation.

La file

Comment servir les éléments dans l’ordre d’arrivée ?

Un besoin concret : attendre son tour

Guichet

File d’attente

Le premier arrivé est le premier servi. On arrive par le fond, on part par la tête.

Les documents sortent dans l’ordre où ils ont été envoyés.
Réseau

Paquets d’un routeur

Les paquets attendent leur tour pour être transmis, dans l’ordre d’arrivée.
Une file est une structure où l’on ajoute à la fin et où l’on retire au début : le premier entré est le premier sorti. En anglais : FIFO (first in, first out).

Avec un tableau : le piège du décalage

Première idée : le premier élément est toujours dans la case 0. Pour défiler, on retire la case 0 et on décale tout le monde d’une case vers la gauche.
On retrouve le défaut du chapitre 2 : défiler coûte n − 1 décalages, donc Θ(n). Pour une file de un million d’éléments, c’est inacceptable.
Meilleure idée : ne rien décaler. On garde une variable début : l’indice du premier élément. Défiler, c’est seulement avancer début d’une case.
Problème : à force d’avancer, on arrive au bout du tableau alors qu’il reste de la place au début. Solution : revenir à la case 0 après la dernière case. C’est le tableau circulaire.

Le tableau circulaire

Trois variables
  • t : le tableau, de N cases
  • début : indice du premier élément
  • taille : nombre d’éléments présents
Pour avancer d’une case en bouclant, on écrit (i + 1) mod N. Avec N = 6 : après la case 5, on retombe sur la case 0. (mod est le reste de la division, % en C.)
enfiler(x):
    t[(début + taille) mod N] ← x
    taille ← taille + 1
défiler():
    x ← t[début]
    début ← (début + 1) mod N
    taille ← taille - 1
    retourner x
Aucun décalage : enfiler et défiler coûtent Θ(1). Limite : la file est pleine quand taille = N.

Avec une liste chaînée : deux pointeurs

Retirer au débutFacile : c’est la suppression en tête, en Θ(1).
Ajouter à la finAvec seulement tete, il faut parcourir la liste (chapitre 3) : Θ(n).
Astuce : une seconde variable queue désigne le dernier nœud. On accroche le nouveau nœud au bout, sans rien parcourir.

À quoi sert une file ?

Système

Tâches en attente

Le système d’exploitation range les tâches prêtes dans une file : chacune passe à son tour sur le processeur (tourniquet).
Réseau

Paquets en transit

Un routeur met les paquets dans une file. Si elle est pleine, les nouveaux paquets sont perdus.

Parcours en largeur

TD · Exercices 1 à 3 : la mémoire

Cherchez seul quelques minutes, puis révélez la solution.

Exercice 1 
int a = 3, b = 4;
int *p = &a;
int *q = &b;
*p = *q;
q = p;
*q = 0;
Que valent a et b à la fin ? Vers quoi pointe q ?
*p = *q : a prend 4. q = p : q désigne a. *q = 0 : a vaut 0. a = 0, b = 4, q désigne a.
Exercice 2 
int *p;
*p = 10;
Quel est le problème ?
p n’a pas été initialisé : il contient une adresse au hasard. Écrire dedans plante, ou abîme la mémoire. Il fallait p = malloc(…) ou p = &a.
Exercice 3 
Noeud *n = malloc(sizeof(Noeud));
n->valeur = 1;
free(n);
printf("%d", n->valeur);
Quel est le problème ?
Après free(n), n est un pointeur pendant : le bloc ne nous appartient plus. Remettre n = NULL après le free évite l’erreur.

TD · Exercices 7 et 8 : pointeurs de pointeurs

Exercice 7 
int a = 1, b = 2;
int *p = &a;
int **pp = &p;
**pp = 10;
*pp = &b;
**pp = 20;
Que valent a et b à la fin ? Vers quoi pointe p ?
**pp = 10 : a vaut 10. *pp = &b : p reçoit l’adresse de b, donc p désigne b. **pp = 20 : b vaut 20. a = 10, b = 20, p désigne b.
Exercice 8
Une matrice de 3 lignes et 4 colonnes est allouée avec int **m. Combien faut-il de malloc ? De free ? Dans quel ordre libère-t-on ? Quelle est la valeur de m[2][3] si m[i][j] = i * 4 + j ?
4 malloc (le tableau de 3 pointeurs, puis les 3 lignes) et 4 free : les 3 lignes d’abord, le tableau de pointeurs en dernier. m[2][3] = 2 × 4 + 3 = 11.

Exercice 9
File vide. On fait : enfiler 1, enfiler 2, enfiler 3, défiler, enfiler 4, défiler, défiler. Quelles valeurs sortent, dans quel ordre ? Que reste-t-il ? Comparez avec l’exercice 5 (pile).

Exercice 10
Tableau circulaire de N = 5 cases, début = 3, taille = 4. Dans quelles cases se trouvent les éléments ? Où enfiler écrit-il ? Quelle est la valeur de début après un défiler ?
Éléments en cases 3, 4, 0, 1 (on boucle après la 4). enfiler écrit en (3 + 4) mod 5 = 2. Après un défiler : début = (3 + 1) mod 5 = 4.

À retenir

Pointeur : une variable qui contient une adresse. p est l’adresse, *p est la case. NULL ne désigne rien.
Pile : variables locales, durée automatique. Tas : blocs de malloc, durée choisie. Un malloc, un free.
Liste chaînée : des nœuds reliés par des adresses. Insertion en tête Θ(1), accès au i-ème Θ(n). L’ordre des affectations décide si la liste survit.
Tableau ou liste : on choisit selon les opérations les plus fréquentes.
Pile : dernier entré, premier sorti, toutes les opérations en Θ(1). Parenthèses et notation postfixe sont ses applications classiques.
File : premier entré, premier sorti. Avec un tableau circulaire ou une liste avec tete et queue, enfiler et défiler coûtent Θ(1).
