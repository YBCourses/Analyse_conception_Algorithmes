1Algorithme et complexité

Un algorithme est une suite finie d’instructions précises qui transforme des données d’entrée en un résultat. Un même problème peut être résolu par plusieurs algorithmes, tous corrects mais pas tous aussi coûteux.
ExempleCalculer 1 + 2 + … + 100. Additionner un par un demande 99 additions. La formule n(n+1)/2 = 100 × 101 ÷ 2 = 5 050 demande 3 opérations. Même résultat, travail très différent.

Trois qualités d’un algorithme

  • Correct : il donne le bon résultat pour toutes les entrées, y compris les cas limites.
  • Rapide : il demande peu d’opérations. On parle de complexité en temps.
  • Économe : il demande peu de mémoire en plus de l’entrée. On parle de complexité en espace.

Le jeu du nombre secret

Je pense à un nombre entre 1 et 100. Deux stratégies : demander 1, puis 2, puis 3… (jusqu’à 100 questions), ou demander toujours le milieu de ce qui reste (au plus 7 questions, car 2⁷ = 128 ≥ 100). La seconde est la recherche dichotomique (du grec dicha, en deux, et tomê, coupe). Elle exige une liste triée : en regardant le milieu, on sait de quel côté se trouve la réponse. La première est la recherche séquentielle.

On compte des opérations, pas des secondes : le nombre d’opérations ne dépend ni de la machine, ni du langage, ni du compilateur. C’est une propriété de l’algorithme.

2Compter les opérations

Le modèle de coût

On se met d’accord sur ce qui coûte 1 : une affectation (s ← 0), une comparaison (i < n), un calcul simple (s + t[i]), un accès à une case (t[i]).

Exemple : la somme d’un tableau

fonction somme(t, n):
    s ← 0
    pour i de 0 à n-1 faire
        s ← s + t[i]
    retourner s

Pour chaque ligne, on multiplie son coût par le nombre de fois qu’elle est exécutée.

OpérationCoûtExécutionsTotal
s ← 0111
i ← 0111
test i < n1n + 1n + 1
i ← i + 11nn
s ← s + t[i]1nn
retourner s111
T(n) = 1 + 1 + (n + 1) + n + n + 13n + 4

Il y a n + 1 tests : n tests réussis, plus un dernier test raté qui arrête la boucle. Vérification : pour n = 3, 5 et 8, la formule donne 13, 19 et 28, exactement ce que compte la simulation du cours.

Un autre codage donnerait par exemple 5n + 1. Dans les deux cas, quand n double, le travail double aussi : le coût est linéaire. La constante exacte importe peu, la façon dont le coût grandit importe beaucoup.

Trois notions à bien comprendre

log₂ n est le nombre de fois qu’on peut diviser n par 2 avant d’arriver à 1. Par exemple log₂ 1 024 = 10, car 1 024 → 512 → … → 1 en 10 divisions. Quand n double, il n’y a qu’une division de plus.
n² se lit « n au carré » et vaut n × n. Il apparaît quand chaque élément est mis en relation avec tous les autres. Exemple : dans un groupe de n personnes, chacune serre la main des n − 1 autres ; une poignée de main comptant pour deux, il y en a n(n − 1)/2, soit environ n²/2. Si n double, c’est environ 4 fois plus.
2ⁿ vaut 2 × 2 × … × 2, avec n facteurs. Un ensemble de n éléments possède 2ⁿ sous-ensembles, car chaque élément est « pris ou laissé ». Chaque élément ajouté double le nombre de cas : 10 éléments donnent 1 024 cas, 30 éléments plus d’un milliard.

4Écrire la complexité : O, Ω, Θ

Pourquoi simplifier ?

Prenons T(n) = 2n² + 50n + 1 000. Pour n = 10, la constante 1 000 domine. Pour n = 100, c’est 2n² (20 000 contre 5 000 et 1 000). Pour n = 1 000, 2n² vaut 2 000 000 et écrase le reste. À grande taille, un seul terme gagne.

Deux gestes pour simplifier

  1. Garder le terme dominant et jeter les autres : 7n³ + 100n² + 3n log n + 9 → 7n³.
  2. Supprimer la constante multiplicative : 7n³ → n³. Résultat : T(n) = Θ(n³).

Pour composer des étapes : instructions qui s’enchaînent, on garde le plus grand ; boucles imbriquées, on multiplie.

Trois façons d’encadrer une croissance

NotationIdéeDéfinition
f = O(g)Le plafond : « pas plus que… »il existe c > 0 et n₀ tels que, pour tout n ≥ n₀, f(n) ≤ c · g(n)
f = Ω(g)Le plancher : « au moins… »il existe c > 0 et n₀ tels que, pour tout n ≥ n₀, f(n) ≥ c · g(n)
f = Θ(g)Le couloir : « de l’ordre de… »f = O(g) et f = Ω(g)
Exemple à la main : f(n) = 3n² + 5n + 2Avec c = 4 : f(n) ≤ 4n² est faux pour n de 1 à 5 (à n = 5, 102 contre 100) mais vrai dès n = 6 (140 ≤ 144), et cela ne change plus, car 4n² − f(n) = n² − 5n − 2 ne fait que croître. On a trouvé c = 4 et n₀ = 6, donc f(n) = O(n²). Avec c = 3, f(n) ≥ 3n² pour tout n, donc f(n) = Ω(n²). Conclusion : f(n) = Θ(n²).

Trois pièges

  • Le signe « = » n’est pas une égalité : n = O(n²) est vrai, mais n n’est pas égal à n².
  • O est une borne, pas un temps exact. Un algorithme linéaire est aussi O(n²), mais c’est peu informatif : préférez Θ quand vous le pouvez.
  • Pour de petites tailles, un algorithme en n² peut battre un algorithme en n log n. La notation décrit le comportement à grande échelle.

7La récursivité

Une fonction est récursive quand elle s’appelle elle-même, sur un problème plus petit. Elle a besoin de deux ingrédients : un cas de base (le problème est si petit qu’on connaît la réponse) et un appel récursif qui rapproche du cas de base.

Exemple : la factorielle

fonction fact(n):
    si n = 0 alors retourner 1
    retourner n × fact(n-1)

Pour calculer fact(4), on descend : fact(4) attend fact(3), qui attend fact(2), qui attend fact(1), qui attend fact(0). Le cas de base répond 1. Puis on remonte : la réponse est rendue à l’appel qui attendait, qui calcule et rend la sienne à son tour.

fact(4) = 4 × fact(3)
  fact(3) = 3 × fact(2)
    fact(2) = 2 × fact(1)
      fact(1) = 1 × fact(0)
        fact(0) = 1                  ← cas de base : la descente s'arrête
      fact(1) = 1 × 1 = 1            ← la réponse remonte
    fact(2) = 2 × 1 = 2
  fact(3) = 3 × 2 = 6
fact(4) = 4 × 6 = 24

La pile d’appels

Chaque appel en cours occupe une place en mémoire : une « fiche » posée sur une pile. Elle est retirée quand l’appel rend sa réponse. Sans cas de base, la fonction s’appelle indéfiniment : les fiches s’empilent jusqu’à saturer la mémoire (erreur de dépassement de pile, ou stack overflow).

fonction fact(n):
    retourner n × fact(n-1)         // jamais d'arrêt !

Coût de la factorielle

Chaque appel fait une multiplication puis appelle fact(n−1) : T(n) = T(n−1) + 1. En déroulant : T(n) = T(n−2) + 2 = T(n−3) + 3 = … = T(0) + n. Il y a n + 1 appels : le coût est linéaire.

Fibonacci : quand les appels se répètent

La suite 0, 1, 1, 2, 3, 5, 8, 13… : chaque nombre est la somme des deux précédents.

fonction fib(n):
    si n ≤ 1 alors retourner n          // deux cas de base : fib(0) = 0 et fib(1) = 1
    retourner fib(n-1) + fib(n-2)

Chaque appel en lance deux : on obtient un arbre d’appels. Dans l’arbre de fib(5), fib(3) apparaît 2 fois, fib(2) 3 fois : le même travail est refait. Le nombre d’appels croît presque comme 2ⁿ.

8Diviser pour régner

Une stratégie en trois temps

  1. Diviser : couper le problème en sous-problèmes plus petits (par exemple deux moitiés).
  2. Résoudre chaque sous-problème, par le même procédé (récursivité). Un problème trivial est le cas de base.
  3. Combiner les réponses en une réponse au problème de départ.

Exemple : le tri fusion

Pour trier un paquet de n nombres : on le coupe en deux moitiés, on fait trier chaque moitié, puis on fusionne les deux moitiés triées.

Fusionner deux paquets triés : on regarde le premier nombre de chaque paquet, le plus petit passe dans le résultat, et on recommence. Chaque nombre n’est déplacé qu’une fois : fusionner n nombres coûte au plus n opérations.

[5 2 8 1 9 3 7 4]                         ← diviser
[5 2 8 1]   [9 3 7 4]
[5 2] [8 1]   [9 3] [7 4]
[5] [2] [8] [1]   [9] [3] [7] [4]         ← un seul nombre : déjà trié (cas de base)
[2 5] [1 8]   [3 9] [4 7]                 ← combiner : 4 fusions, ≤ 8 opérations
[1 2 5 8]   [3 4 7 9]                     ← 2 fusions, ≤ 8 opérations
[1 2 3 4 5 7 8 9]                         ← 1 fusion, ≤ 8 opérations

L’équation de récurrence

T(n) = 2 · T(n/2) + n
  • 2 : il y a deux sous-problèmes (les deux moitiés) ;
  • T(n/2) : chaque moitié a n/2 nombres, la trier coûte T(n/2) ;
  • + n : la fusion coûte au plus n opérations.

Cas de base : T(1) = 1.

Résoudre : l’arbre de récursion

À chaque niveau de l’arbre, le nombre de morceaux double mais leur taille est divisée par 2 : le coût de recollage du niveau reste égal à n. Il y a log₂ n niveaux, donc T(n) = n × log₂ n, soit Θ(n log n). Pour n = 8 : 3 niveaux × 8 = 24.

Le théorème maître

Les équations de « diviser pour régner » ont la forme T(n) = a · T(n/b) + nᵈ où :

  • a est le nombre de sous-problèmes ;
  • b est le facteur de réduction de la taille ;
  • d est l’exposant du travail de recollage nᵈ (d = 0 : constant ; d = 1 : n ; d = 2 : n²).

int recherche_sequentielle(int t[], int n, int x) {

Recherche dichotomique (tableau trié)

C
int recherche_dichotomique(int t[], int n, int x) {
    int debut = 0, fin = n - 1, milieu;
    while (debut <= fin) {
        milieu = (debut + fin) / 2;
        if (t[milieu] == x) return milieu;
        else if (t[milieu] < x) debut = milieu + 1;
        else fin = milieu - 1;
    }
    return -1;
}
Python
def recherche_dichotomique(t, x):
    debut, fin = 0, len(t) - 1
    while debut <= fin:
        milieu = (debut + fin) // 2
        if t[milieu] == x:
            return milieu
        elif t[milieu] < x:
            debut = milieu + 1
        else:
            fin = milieu - 1
    return -1

Factorielle et Fibonacci récursifs

C
long fact(int n) {
    if (n == 0) return 1;          /* cas de base */
    return n * fact(n - 1);        /* appel récursif */
}

long fib(int n) {
    if (n <= 1) return n;          /* deux cas de base */
    return fib(n - 1) + fib(n - 2);
}
Python
def fact(n):
    if n == 0:                     # cas de base
        return 1
    return n * fact(n - 1)         # appel récursif


def fib(n):
    if n <= 1:                     # deux cas de base
        return n
    return fib(n - 1) + fib(n - 2)

Tri par insertion (utilisé en TP)

On parcourt le tableau ; pour chaque élément, on le met de côté, on décale vers la droite les éléments plus grands, puis on le pose dans le trou. Coût au pire (tableau trié à l’envers) : 1 + 2 + … + (n−1) décalages, soit Θ(n²). Au mieux (déjà trié) : Θ(n).

C
void tri_insertion(int t[], int n) {
    int i, j, cle;
    for (i = 1; i < n; i++) {
        cle = t[i];
        j = i - 1;
        while (j >= 0 && t[j] > cle) {
            t[j + 1] = t[j];
            j--;
        }
        t[j + 1] = cle;
    }
}
Python
def tri_insertion(t):
    for i in range(1, len(t)):
        cle = t[i]
        j = i - 1
        while j >= 0 and t[j] > cle:
            t[j + 1] = t[j]
            j -= 1
        t[j + 1] = cle

i ← n

  opération()
  i ← i / 2
Solution
i est divisé par 2 à chaque tour : ⌊log₂ n⌋ + 1 passages, donc Θ(log n).

Exercice 4 (supplémentaire)

pour i de 1 à n faire
  pour j de 1 à n faire
    pour k de 1 à n faire
      opération()
Solution
Trois boucles imbriquées de n tours : n × n × n, donc Θ(n³).

Exercice 5 (supplémentaire)

i ← 1
tant que i < n faire
  opération()
  i ← i + 2
Solution
i prend les valeurs 1, 3, 5, … : environ n/2 passages. La constante ½ disparaît : Θ(n). (Ce n’est pas un logarithme : on ajoute 2, on ne multiplie pas.)

Récurrences

Exercice 6

T(n) = T(n/2) + 1
Solution
a = 1, b = 2, d = 0. log₂ 1 = 0 = d : cas 2, Θ(log n).

Exercice 7

T(n) = 2T(n/2) + n²
Solution
a = 2, b = 2, d = 2. log₂ 2 = 1 < d : cas 3, Θ(n²).

Exercice 8 (sans théorème maître)

T(n) = T(n−1) + n
Solution
On déroule : T(n) = n + (n−1) + … + 1 = n(n+1)/2, donc Θ(n²). Le théorème maître ne s’applique pas : on ne divise pas n par b.

Exercice 9 (supplémentaire)

T(n) = 3T(n/3) + n
Solution
a = 3, b = 3, d = 1. log₃ 3 = 1 = d : cas 2, Θ(n log n).

Exercice 10 (supplémentaire)

T(n) = T(n/2) + n
Solution
a = 1, b = 2, d = 1. log₂ 1 = 0 < d : cas 3, Θ(n). La racine domine : n + n/2 + n/4 + … ≈ 2n.

Classer des expressions

Exercice 11

Donnez la complexité (en Θ) de : a) 5n³ + 2n² + 7 · b) 5n log n + 100n + 7 · c) n² + 2ⁿ · d) 4 000 000.
Solution
a) Θ(n³) · b) Θ(n log n) · c) Θ(2ⁿ) · d) Θ(1) : une constante, aussi grande soit-elle, ne dépend pas de n.
