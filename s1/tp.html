Chaque fichier contient recherche_sequentielle, recherche_dichotomique et tri_insertion, plus des fonctions partie1() à partie4() qui font les mesures. Deux endroits sont à compléter : TODO 1 et TODO 2. Au départ, seule la partie 1 est active.

Un tableau trié de n nombres est construit pour vous : 0, 2, 4, 6, …. On cherche la valeur 2n + 1. Elle est absente et plus grande que tous les éléments : c’est le pire cas pour les deux méthodes.

Partie 3 · Un tri quadratique 15 min

3.1 · TODO 2 Complétez tri_insertion dans les deux fichiers. Le principe, en pseudo-code :
pour i de 1 à n-1 faire
    cle ← t[i]                         // on met t[i] de côté
    j ← i - 1
    tant que j ≥ 0 et t[j] > cle faire // on décale vers la droite
        t[j+1] ← t[j]                  // les éléments plus grands que cle
        j ← j - 1
    t[j+1] ← cle                       // on pose cle dans le trou

Aide

Le compilateur affiche une erreur
Vérifiez que vous avez bien ajouté un point-virgule à la fin de la ligne du TODO 1. En C, compteur est de type long : on l’affiche avec %ld.
La dichotomique affiche 0 comparaison
C’est normal tant que le TODO 1 n’est pas fait : la ligne qui compte manque.
Mes temps sont tous égaux à 0
Le chronomètre n’est pas assez précis pour une opération très courte. Augmentez le nombre de répétitions (reps_dic dans les deux fichiers).
Le tri ne trie pas
Testez à la main avec 5, 2, 8, 1, 9. Les erreurs classiques : oublier de poser cle après la boucle, ou partir de i = 0 au lieu de i = 1. En Python, retirez le mot pass une fois la boucle écrite.
Mon ordinateur est lent ou très rapide
Aucun souci : seuls les rapports comptent. Si une mesure dure plus de 30 secondes, diminuez la taille la plus grande dans la fonction concernée.
Le bouton d’export ne télécharge rien
Utilisez « Copier le JSON », collez le contenu dans un fichier texte nommé TP1_NOM_Prenom.json, puis envoyez ce fichier.
